## 보안 주체와 증명
식별|사용자가 계정명 등으로 자신이 누구라고 주장하는지 시스템에 제시하는 단계이다.
인증|제시된 신원의 주체가 실제 그 주체인지 비밀번호·키 등의 증거로 확인하는 단계이다.
인가|확인된 주체가 어떤 자원에 어떤 동작을 할 수 있는지 권한 정책으로 판단하는 단계이다.
책임 추적성|행위를 특정 주체와 연결할 수 있도록 식별과 기록을 유지하여 사후 설명 가능하게 한다.
부인 방지|행위자가 나중에 자신이 수행한 전송이나 서명 사실을 거짓으로 부정하기 어렵게 증거를 제공한다.
개인정보 최소 수집|업무 목적에 필요한 정보만 수집하고 불필요한 개인 데이터 노출을 줄이는 원칙이다.
## 자산·위험 관리
정보 자산|보호 가치가 있는 데이터·시스템·서비스 등 조직의 관리 대상을 말한다.
보안 위협|취약점을 이용하거나 사고를 일으켜 자산에 피해를 줄 수 있는 사건이나 원인을 뜻한다.
취약점|위협이 악용할 수 있는 설계·구현·운영·통제상의 약점이다.
위험 수용|평가한 잔여 위험을 정해진 책임자가 이해하고 추가 대응 없이 감수하기로 결정한다.
위험 회피|위험을 유발하는 업무나 방식을 수행하지 않도록 변경하여 해당 노출을 없앤다.
위험 이전|보험이나 계약 등의 수단으로 위험으로 인한 일부 손실 부담을 다른 주체에 분담시킨다.
## 접근 통제 모델
DAC|자원 소유자에게 접근 권한을 부여·회수할 재량을 주는 접근 통제 모델이다.
MAC|보안 등급과 주체의 인가 수준 등 중앙 정책으로 접근을 강제하는 통제 모델이다.
RBAC|개별 사용자마다 권한을 직접 나열하기보다 직무 역할에 권한을 묶고 사용자를 역할에 연결한다.
ABAC|주체·자원·동작·환경의 속성들을 정책 조건으로 평가하여 접근을 결정한다.
ACL|자원별로 어떤 주체가 어떤 동작을 할 수 있는지 항목 목록으로 관리한다.
직무 분리|한 사람이 중요한 업무의 상충되는 권한을 모두 가지지 못하도록 역할을 나누어 오용을 줄인다.
## 인증 정보 방어
비밀번호 솔트|같은 비밀번호라도 저장 해시가 달라지도록 사용자별 임의 값을 더하며 비밀일 필요는 없다.
비밀번호 페퍼|해시 데이터베이스와 분리하여 비밀로 관리하는 추가 값을 비밀번호 처리에 사용한다.
느린 비밀번호 해싱|반복 계산이나 메모리 비용을 의도적으로 높여 대량 오프라인 추측 공격 비용을 늘린다.
일회용 비밀번호|한 번의 인증이나 짧은 유효 기간에만 사용할 수 있는 인증 값을 생성한다.
로그인 속도 제한|계정·주소·문맥 등별 시도 빈도를 제한하여 온라인 비밀번호 추측 공격을 완화한다.
패스키|도메인에 연결된 공개키 자격 증명을 사용하여 사용자가 서버에 재사용 비밀번호를 보내지 않고 인증하게 한다.
## 대칭 암호의 구성
AES|블록 크기 128비트와 128·192·256비트 키를 사용하는 대표적인 대칭 블록 암호이다.
DES|56비트 유효 키를 사용하는 오래된 블록 암호로 현재의 안전한 신규 설계에 채택해서는 안 된다.
3DES|DES를 여러 번 적용하는 과거 대칭 암호로 현대 신규 시스템에서는 사용을 피하고 대체해야 한다.
ChaCha20|카운터와 nonce 등을 사용해 키 스트림을 만드는 대표적인 현대 스트림 암호이다.
블록 암호|정해진 길이의 입력 블록을 키에 따라 같은 길이의 블록으로 변환하는 암호 원시 기법이다.
스트림 암호|키 스트림을 생성하고 원문과 결합하여 연속적인 데이터 흐름을 암호화하는 방식이다.
## 공개키와 서명 알고리즘
RSA|큰 정수의 소인수 분해 어려움과 관련된 수학적 기반을 사용하며 적절한 방식으로 암호화나 서명에 활용한다.
Diffie-Hellman|서로 비밀값을 직접 전송하지 않고 공개값 교환으로 공통 비밀을 합의하는 키 교환 기법이다.
DSA|유한체 이산 로그 문제에 기반한 디지털 서명 알고리즘으로 암호화 알고리즘과 구별된다.
ECC|타원곡선 위의 연산과 이산 로그 어려움을 기반으로 공개키 기법을 구성하는 암호 기술 계열이다.
ECDSA|타원곡선 암호 수학을 이용하여 디지털 서명을 생성·검증하는 DSA 계열 알고리즘이다.
EdDSA|에드워즈 곡선 계열을 사용하는 디지털 서명 방식으로 Ed25519 같은 구현이 알려져 있다.
## 암호 운용과 무결성
ECB 모드|같은 키에서 같은 평문 블록을 항상 같은 암호문 블록으로 만들어 패턴이 드러날 수 있는 블록 운용 모드이다.
CBC 모드|이전 암호문 블록과 현재 평문 블록을 결합해 암호화하며 첫 블록에 적절한 IV가 필요한 모드이다.
CTR 모드|카운터 블록을 암호화해 만든 키 스트림과 원문을 결합하며 같은 키에서 카운터 입력을 재사용하면 위험한 모드이다.
GCM 모드|카운터 기반 암호화와 인증 태그를 결합한 인증 암호 모드로 같은 키의 nonce 재사용을 피해야 한다.
HMAC|해시 함수와 비밀키를 결합하여 메시지 무결성과 키 보유자의 인증을 제공하는 메시지 인증 코드이다.
해시 충돌 저항성|서로 다른 두 입력이 같은 해시값을 갖도록 찾는 것이 계산상 어려워야 하는 성질이다.
## 인증서와 PKI
CA|공개키와 주체의 연결을 검증하여 인증서에 서명하는 신뢰 기관이다.
X.509 인증서|주체·발급자·공개키·유효 기간·서명 등 공개키 신뢰 정보를 표준 구조로 담는 전자 문서이다.
인증서 체인|말단 인증서에서 중간 발급자를 거쳐 신뢰 기준까지 서명을 연결해 검증하는 경로이다.
CRL|인증서 발급자가 폐기한 인증서들의 정보를 서명된 목록으로 제공하는 방식이다.
OCSP|특정 인증서의 폐기 상태를 온라인 응답자로부터 조회하는 프로토콜이다.
CSR|인증서 발급을 위해 주체 정보와 공개키 등을 담아 서명한 인증 요청 자료이다.
## TLS와 신뢰 경계
TLS 서버 인증|접속 서버가 제시한 인증서의 신뢰 경로·호스트 이름·유효성 등을 확인하여 상대를 검증한다.
상호 TLS|서버뿐 아니라 클라이언트도 인증서를 제시하여 TLS 연결 양쪽 주체를 인증한다.
순방향 안전성|현재의 장기 비밀키가 나중에 유출되어도 과거 세션의 비밀이 함께 복구되지 않도록 하는 성질이다.
SNI|TLS 연결 설정 과정에서 클라이언트가 접속하려는 호스트 이름을 전달하여 서버가 적절한 설정을 선택하게 한다.
TLS 종료 지점|로드 밸런서 등에서 암호 연결을 해제한 뒤 내부 통신의 보안 책임과 새 신뢰 경계를 검토해야 하는 위치이다.
인증서 이름 불일치|인증서가 유효해 보여도 접속한 호스트가 인증서의 허용 이름에 없으면 상대 신원 검증이 실패하는 상황이다.
## 서버 입력 취약점
명령어 삽입|외부 입력이 운영체제 명령 구문에 섞여 의도하지 않은 명령을 실행하게 하는 취약점이다.
경로 순회|입력 경로의 상위 디렉터리 이동 등을 악용하여 허용 영역 밖 파일에 접근하는 취약점이다.
XXE|부적절하게 설정된 XML 파서가 외부 엔티티를 해석하여 파일 노출이나 외부 요청을 일으키는 취약점이다.
SSRF|서버가 외부 입력으로 지정된 주소에 요청하게 만들어 내부·메타데이터 서비스 등에 접근시키는 공격이다.
안전하지 않은 역직렬화|신뢰할 수 없는 직렬화 데이터를 복원하는 과정에서 임의 객체 동작이나 코드 실행 등이 발생하는 문제이다.
LDAP 삽입|입력이 디렉터리 검색 필터 구문에 섞여 인증·검색 조건을 의도와 다르게 바꾸는 취약점이다.
## 브라우저 보안 정책
CSP|허용할 스크립트·리소스 출처 등을 선언하여 브라우저의 콘텐츠 실행·로딩을 제한하는 보안 정책이다.
HSTS|브라우저가 정해진 기간 동안 해당 호스트에 HTTPS로만 접속하도록 지시하는 정책이다.
HttpOnly 쿠키|브라우저의 일반 스크립트 API로 해당 쿠키를 읽지 못하도록 제한하는 속성이다.
Secure 쿠키|일반적으로 HTTPS 같은 안전한 연결에서만 쿠키를 전송하도록 제한하는 속성이다.
동일 출처 정책|브라우저가 스크립트의 다른 출처 자원 읽기 등을 제한하며 출처는 스킴·호스트·포트 조합으로 구분한다.
CORS|서버가 응답 헤더로 허용 출처 등을 알려 브라우저의 교차 출처 읽기를 통제된 방식으로 허용한다.
## 메모리 방어 기법
스택 카나리|함수 반환 전 특정 보호 값의 변화를 확인하여 일부 스택 손상을 탐지한다.
ASLR|프로세스 메모리 배치를 무작위화하여 공격자가 코드·자료 주소를 예측하기 어렵게 한다.
NX 메모리 보호|데이터 영역 같은 지정 페이지에서 명령을 실행하지 못하게 하여 주입 코드 실행을 제한한다.
형식 문자열 취약점|외부 입력을 printf류 함수의 형식 문자열로 사용해 임의 읽기·쓰기 등의 위험을 만드는 문제이다.
정수 크기 검사 누락|크기 계산의 오버플로 등을 검사하지 않아 작은 버퍼를 할당하고 더 많은 데이터를 쓰게 될 수 있는 문제이다.
TOCTOU|검사한 상태와 실제 사용하는 시점 사이에 자원 상태가 바뀌는 경쟁을 악용하는 문제이다.
## 네트워크 공격
중간자 공격|통신 양측 사이에 끼어 메시지를 가로채거나 바꾸며 상대를 사칭하는 공격이다.
ARP 스푸핑|거짓 IP-MAC 대응 정보를 보내 로컬 네트워크의 트래픽을 공격자 쪽으로 유도한다.
DNS 캐시 포이즈닝|거짓 이름 해석 정보를 캐시에 심어 사용자를 잘못된 주소로 유도한다.
SYN 플러드|TCP 연결 설정을 끝내지 않는 다수 요청 등으로 연결 대기 자원을 소모시키는 공격이다.
스머프 공격|출발지를 피해자로 위조한 ICMP 요청과 브로드캐스트 응답 증폭을 악용하는 서비스 거부 공격이다.
UDP 증폭 공격|출발지를 피해자로 위조하고 작은 요청에 큰 UDP 응답을 보내는 서비스를 악용하여 트래픽을 늘린다.
## 악성 코드 구분
바이러스|다른 실행 파일이나 문서 등에 붙어 실행 과정에서 복제·전파되는 악성 코드이다.
웜|스스로 네트워크 등을 통해 전파되는 독립 실행형 악성 코드이다.
트로이 목마|정상적이거나 유용한 프로그램으로 위장하여 숨은 악의적 동작을 수행한다.
랜섬웨어|데이터 암호화나 접근 차단 등을 통해 복구 대가를 요구하는 악성 코드이다.
루트킷|권한을 은밀히 유지하고 프로세스·파일 등 악성 활동의 존재를 숨기는 도구 집합이다.
백도어|정상 인증·접근 경로를 우회하여 시스템에 들어갈 수 있도록 숨겨 놓은 통로이다.
## 보안 검증 방법
SAST|실행 전 소스나 중간 표현을 정적으로 분석하여 보안 결함 후보를 찾는 검사이다.
DAST|실행 중인 애플리케이션에 요청을 보내 외부 관찰로 보안 취약점을 찾는 검사이다.
SCA|사용한 오픈소스 등 외부 구성 요소의 버전·알려진 취약점·라이선스 등을 분석한다.
퍼징|다양하거나 비정상적인 입력을 자동으로 반복 제공하여 비정상 종료와 경계 처리 결함을 찾는다.
침투 테스트|허가된 범위에서 공격자의 관점으로 실제 악용 가능성과 보안 영향을 확인한다.
위협 모델링|설계 단계부터 자산·신뢰 경계·데이터 흐름과 가능한 위협을 체계적으로 분석한다.
## 보안 운영 체계
SIEM|여러 시스템의 보안 로그를 수집·상관 분석하여 탐지와 조사를 지원한다.
SOAR|보안 경보 조사와 대응 절차를 플레이북 등으로 연계·자동화한다.
SOC|조직의 보안 모니터링·탐지·대응을 수행하는 운영 조직 또는 관제 센터이다.
EDR|단말의 실행·행위 정보를 수집하고 위협을 탐지·조사·대응하는 보안 기능이다.
WAF|웹 애플리케이션 계층의 요청을 분석하여 SQL 삽입 등 악성 패턴을 차단하는 방화벽이다.
NAC|네트워크에 접속하는 단말의 신원·보안 상태 등을 확인하여 접속 허용 범위를 통제한다.
## 키와 비밀 관리
키 회전|하나의 암호키를 영구히 쓰지 않고 정해진 정책이나 사건에 따라 새 키로 교체한다.
키 폐기|유출·사용 종료 등으로 더는 키를 신뢰하지 않도록 무효화하고 필요 시 안전하게 제거한다.
키 에스크로|정해진 복구·통제 목적을 위해 키 자료를 별도 신뢰 주체에게 맡겨 보관하는 체계이다.
단기 자격 증명|장기 고정 비밀 대신 짧은 유효 기간을 가진 인증 정보를 발급하여 노출 시 악용 기간을 줄인다.
KMS|암호키 생성·권한·수명 주기·암호 연산 접근 등을 중앙에서 관리하는 서비스 또는 체계이다.
HSM|키 보호와 암호 연산을 전용 보안 하드웨어의 경계 안에서 수행하는 장치이다.
## 시스템 강화
샌드박스|실행 코드가 접근할 수 있는 파일·네트워크·자원 범위를 격리하여 피해 범위를 줄인다.
허용 목록 정책|허용된 항목을 명시하고 목록에 없는 실행·통신 등을 기본적으로 거부한다.
불필요 서비스 제거|업무에 쓰지 않는 데몬·포트·패키지를 꺼서 공격 표면을 줄이는 강화 조치이다.
보안 구성 기준선|운영체제·서비스의 안전한 설정을 공통 기준으로 정하고 일탈 여부를 검사한다.
파일 무결성 모니터링|중요 파일의 해시·속성 변화를 비교하여 승인되지 않은 변경을 탐지한다.
특권 계정 관리|관리자 권한 사용을 승인·제한·기록하며 필요 시에만 일시 부여하도록 통제한다.
## 가상화와 컨테이너
하이퍼바이저|여러 가상 머신의 가상 하드웨어와 자원 사용을 관리하는 가상화 계층이다.
타입 1 하이퍼바이저|일반 호스트 운영체제 위의 응용이 아니라 물리 하드웨어 위에서 직접 동작하는 형태이다.
타입 2 하이퍼바이저|일반 호스트 운영체제 위에서 프로그램으로 실행되는 가상화 형태이다.
컨테이너|호스트 커널을 공유하면서 프로세스·파일·자원을 격리하여 애플리케이션 실행 환경을 묶는다.
리눅스 네임스페이스|프로세스 ID·네트워크·마운트 등 시스템 자원이 보이는 범위를 분리하는 커널 기능이다.
cgroups|프로세스 그룹의 CPU·메모리 같은 자원 사용을 제한·계측하는 리눅스 커널 기능이다.
## 클라우드 제공과 구성
PaaS|제공자가 실행 플랫폼과 기반 운영 환경을 관리하고 사용자는 주로 애플리케이션을 배포하는 서비스 모델이다.
SaaS|완성된 소프트웨어 기능을 서비스로 제공하여 사용자가 주로 설정·데이터·이용을 관리하는 모델이다.
퍼블릭 클라우드|제공자가 여러 고객에게 공통 서비스 기반을 제공하는 클라우드 배치 형태이다.
프라이빗 클라우드|한 조직의 전용 사용을 위해 구성된 클라우드 배치 형태이다.
하이브리드 클라우드|전용 환경과 공용 클라우드 등 서로 다른 환경을 연계하여 운용한다.
멀티 클라우드|둘 이상의 클라우드 제공자 서비스를 함께 사용하는 운영 구성이다.
## 확장과 상태
수직 확장|한 서버나 인스턴스에 CPU·메모리 같은 자원을 더 많이 할당한다.
수평 확장|서버나 인스턴스의 개수를 늘려 부하를 여러 노드로 나눈다.
자동 확장|측정 지표나 예약 정책에 따라 실행 인스턴스·자원의 양을 자동으로 조절한다.
무상태 서비스|각 요청 처리가 특정 서버의 이전 요청 세션 상태에 의존하지 않도록 구성한다.
세션 고정|같은 사용자 요청을 가능한 한 같은 백엔드로 보내 로컬 세션 상태를 사용하게 하는 분산 정책이다.
외부 세션 저장소|여러 서버가 같은 사용자 세션 상태를 공유할 수 있도록 세션을 별도 공통 저장소에 둔다.
## 장애 격리와 복원력
페일오버|현재 서비스 노드가 실패하면 대기 또는 다른 정상 노드로 역할을 전환한다.
이중화|핵심 자원을 복수로 구성하여 하나의 실패가 전체 중단으로 이어질 가능성을 줄인다.
쿼럼|분산 의사결정이나 복제 연산에서 정해진 수 이상의 노드 동의를 요구하는 규칙이다.
서킷 브레이커|연속 실패한 의존 서비스 호출을 일시 차단하고 회복 여부를 제한적으로 시험한다.
벌크헤드|자원 풀 등을 분리하여 한 기능의 장애나 고갈이 다른 기능까지 번지지 않게 한다.
지수 백오프|반복 재시도 사이의 대기 간격을 점차 늘려 장애 중 추가 부하를 완화한다.
## 저장 장치 구성
RAID 0|데이터를 여러 디스크에 스트라이핑하되 중복 보호를 제공하지 않아 한 디스크 장애에도 데이터가 손실될 수 있다.
RAID 1|같은 데이터를 여러 디스크에 미러링하여 복사본을 유지한다.
RAID 5|분산 패리티를 사용하여 일반적으로 한 개 디스크 장애를 견디는 저장 배열이다.
RAID 6|서로 독립적인 두 패리티를 유지하여 일반적으로 두 개 디스크 장애를 견디는 저장 배열이다.
RAID 10|미러링 집합들을 스트라이핑하는 조합으로 장애 허용 정도는 실패한 디스크의 위치에 따라 달라진다.
SAN|서버에 블록 수준 저장 장치 접근을 제공하는 전용 저장 네트워크이다.
## 백업과 복구 검증
전체 백업|선택한 데이터 전체를 한 번의 백업 기준으로 복사하여 보관한다.
증분 백업|최근 백업 이후 바뀐 부분만 저장하여 복구 시 기준 백업과 필요한 후속 백업들이 필요하다.
차등 백업|최근 전체 백업 이후 바뀐 모든 부분을 매번 저장한다.
오프사이트 백업|원본 시스템과 지리적으로 떨어진 위치에 복사본을 보관하여 같은 장소의 재해를 대비한다.
불변 백업|정해진 기간 동안 백업을 삭제·덮어쓰기 어렵게 하여 랜섬웨어나 오작동으로부터 보호한다.
복구 훈련|백업 파일의 존재만 확인하지 않고 실제 복원과 서비스 재개 절차를 수행하여 목표 충족 여부를 검증한다.
## 관측성과 서비스 목표
메트릭|CPU 사용률이나 요청 수처럼 시간에 따라 집계·비교할 수 있는 수치 측정 자료이다.
구조화 로그|사건을 키-값 등 기계가 읽기 쉬운 형식으로 남겨 검색·집계·연관 분석을 돕는다.
분산 추적|하나의 요청이 여러 서비스에서 거친 구간과 시간을 연결하여 흐름을 관찰한다.
SLI|서비스의 성공률·지연 같은 실제 측정 성능을 나타내는 서비스 수준 지표이다.
SLO|특정 기간의 SLI가 만족해야 할 내부 목표 수준을 정한 것이다.
SLA|서비스 제공자와 고객 사이에서 서비스 수준과 책임·조건 등을 정한 약정이다.
## 개발 규모와 계획
기능 점수|사용자 관점의 입력·출력·조회·논리 파일·외부 인터페이스 등으로 소프트웨어 기능 규모를 추정한다.
LOC 추정|예상 소스 코드 줄 수를 기반으로 개발 규모나 노력 등을 추정하며 언어·구현 방식의 영향을 받는다.
델파이 기법|전문가들의 익명 의견과 반복 피드백을 통해 추정이나 판단을 수렴시킨다.
COCOMO|소프트웨어 규모와 비용 요인 등을 사용하여 노력·기간을 추정하는 알고리즘 기반 비용 모형 계열이다.
WBS|프로젝트의 전체 범위를 관리 가능한 작은 작업 패키지로 계층 분해한다.
PERT|작업 기간의 낙관·최빈·비관 추정 등을 이용하여 불확실한 일정과 작업 네트워크를 분석한다.
## 일정 통제
간트 차트|시간 축 위에 작업별 시작·기간·진행 상황을 막대로 표시하는 일정 도구이다.
마일스톤|주요 완료나 의사결정 시점을 나타내며 통상 자체 지속 기간을 두지 않는 일정 기준점이다.
주공정|작업 네트워크에서 프로젝트 완료 시간을 결정하며 지연 시 전체 종료에 영향을 주는 경로이다.
총 여유 시간|전체 프로젝트 완료를 늦추지 않는 범위에서 해당 작업을 늦출 수 있는 시간이다.
선행 의존성|다른 작업의 시작이나 완료 조건이 충족되어야 다음 작업을 진행할 수 있다는 일정 관계이다.
자원 평준화|사용 가능한 인력·장비 한계를 고려하여 작업 시점을 조정하고 자원 사용을 균등화한다.
## 획득가치 관리
PV|측정 시점까지 수행할 계획이었던 작업에 배정된 예산 가치이다.
EV|측정 시점까지 실제 완료한 작업을 원래 예산 기준으로 환산한 가치이다.
AC|측정 시점까지 실제 수행 작업에 지출한 비용이다.
CPI|EV를 AC로 나누어 비용 대비 성과를 보는 지수이며 AC가 양수일 때 1보다 작으면 비용 효율이 계획보다 낮다.
SPI|EV를 PV로 나누어 계획 대비 작업 진척을 보는 지수이며 PV가 양수일 때 1보다 작으면 계획보다 진척이 낮다.
BAC|프로젝트 전체에 대해 승인된 완료 시점의 총 예산이다.
## 운영 자동화
IaC|인프라 구성을 선언적·절차적 코드로 정의하여 버전 관리와 재현 가능한 변경을 수행한다.
구성 드리프트|실제 서버 설정이 승인된 코드·기준 구성과 시간이 지나며 달라지는 현상이다.
불변 인프라|실행 중 서버를 수작업으로 계속 고치기보다 변경된 이미지로 새 인스턴스를 교체하는 운영 방식이다.
서비스 메시|서비스 간 통신의 관측·보안·트래픽 정책 등을 공통 인프라 계층에서 제공한다.
구성 관리 도구|여러 시스템의 패키지·파일·서비스 설정을 원하는 상태로 맞추고 일관성을 유지한다.
선언적 운영|자세한 변경 명령 순서보다 원하는 최종 상태를 명시하고 도구가 현재 상태와 차이를 조정하게 한다.
## 기업 시스템 연계
EA|업무·데이터·응용·기술 구조의 관계를 조직 전체 관점에서 정리하여 변화 방향을 일관되게 관리한다.
ISP|조직 전략과 업무 요구를 분석하여 정보시스템의 중장기 추진 방향과 계획을 수립한다.
BPR|기존 절차의 작은 개선을 넘어 핵심 업무 프로세스를 근본적으로 재설계하여 성과 향상을 추구한다.
EAI|서로 다른 기업 응용 시스템들의 데이터·업무 기능을 통합하여 연계하는 접근과 기술이다.
ESB|서비스 간 메시지 전달·변환·라우팅 등을 공통 버스 기반으로 제공하는 통합 인프라이다.
API 게이트웨이|외부 API 요청의 공통 진입점에서 인증·라우팅·요청량 제한 같은 정책을 적용한다.
