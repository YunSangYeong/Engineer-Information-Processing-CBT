## 현재 문제은행

- 기본 JSON에 **1,000개**, 5과목 각각 **200개**가 실제 등록되어 있다. 기존 100개를 모든 필드 그대로 보존하고 과목별180개씩 총900개를 추가했다.
- 자체 제작·내부 검수1,000, 검증대기0, 기출0, 복원0, 숫자 조건 변형0, 목표부족0. 외부 전문가 검수0. AI 일반 지식으로 작성한 비공식 학습 자료이다.
- 기존 원고는 `scripts/generate-bank.py`, 추가 원고는 `scripts/manuscripts/subject-1.txt`~`subject-5.txt`. 과목별30개 단원×6개의 서로 다른 식별 목표로900개를 작성했다. 한 문항을 뒤집거나 보기 순서만 바꾼 추가본이 아니다. 추가900개는 주로 개념 식별형이며 계산형 기출의 난이도·분포를 재현한다고 주장하지 않는다.
- 추가 원고를 대상으로 용어 정의·정답·같은 단원의 다른 보기 의미를 내부 재검토했다. 해설에 정답 설명과 선택된 오답3개의 정의를 함께 제공한다. 자동화 검사는 이 편집 검토나 외부 전문가 검수와 별개이다.
- 기존 100개와 겹칠 수 있던 추가 원고의 인터페이스 계약 설명·키 최소성·비밀 보관 설명을 다른 학습 목표로 교체했다. CHECK의 UNKNOWN 허용, C의 부호 있는/없는 오버플로, Python 가변 객체 참조 등 모호해지기 쉬운 규칙은 조건을 명시했다.
- 모든 출제 연도·회차는 null이다. 새 문항의 저장소 링크는 이 문서의 작성 기록을 가리키며 외부 정답 증빙이 아니다. 기존100개는 ID·정답·해설뿐 아니라 출처 필드까지 보존했다.
- 작성 데이터·원고·양식은 CC BY 4.0, 앱 재사용 코드는 MIT. 제3자 자료를 수록하거나 기출 재배포 권리를 확보했다고 표시하지 않는다.

## 중복과 재현 감사

- NFKC 정규화·공백 제거·소문자화한 본문 고유1,000개. 본문과 정렬된 보기의 지문 고유1,000개. ID 고유1,000개. `IPE-1-001`부터 과목별 `IPE-5-200`까지 기대 ID 범위와 일치한다.
- 학습 목표900개를 원고와 대조하여 문제의 정의·정답 위치·보기의 소속 단원·오답별 해설을 검사한다. 기존100개 직렬화 SHA256은 `6f99d1e1b9eae6fe36e4d304176f85b0bb1584b66c7f20c7a1964989d9bb30e7`로 보존 검사한다.
- 공통 질문 틀을 제외하고 문자3그램 Jaccard 0.38 이상인 유사 후보14쌍을 추출해 내부 검토했다. UPDATE/DELETE, LEFT/RIGHT JOIN, EXISTS/NOT EXISTS, ANY/ALL, args/kwargs, RPO/RTO 등 다른 연산·개념을 구분하므로 유지했다. 판정 이유는 `docs/bank-audit.json`에 기록했다.
- 객체지향과 네트워크에서 같은 정답 명칭 ‘캡슐화’를 쓰는 두 문항은 각각 정보 접근과 계층별 헤더 추가를 묻는 다른 목표이다. 동일 정답 문자열이라는 이유만으로 삭제하지 않았다.
- 이 감사는 의미상 중복이 절대로 없다는 보장이 아니다. 외부 전문가·의미 유사도 모델 검수는 수행하지 않았다.
- 생성기는 고정 ID의 SHA256을 보기 선택·배치 시드로 사용한다. 같은 환경에서 두 번 생성하여 JSON과 CSV 양식의 바이트 일치를 확인했다.
- 현재 JSON SHA256: `3f10ba2f07cca37073298dba280ada3c9fe0881b5788d75f2f6bcce12380ba01`.
- `python3 scripts/audit-bank.py`는 읽기 전용 검사, `--write`는 `docs/bank-audit.json` 보고서만 저장한다. 새 유사 후보는 검토 이유 없이 자동 통과시키지 않는다.

## 배포 사전 확인 및 중단

- GitHub 읽기 및 `git push --dry-run origin HEAD:main`: 성공. dry-run은 파일 반영이나 workflow 실행을 하지 않는다. 새 파일을 포함한 실제 push 성공을 보장하는 검사로 해석하지 않는다.
- Pages 설정 GET `https://api.github.com/repos/YunSangYeong/Engineer-Information-Processing-CBT/pages`: 첫 요청에서 CONNECT403, 목적지HTTP000. 네트워크 터널의 거부이며 GitHub 저장소 권한/Pages 설정 응답은 받지 못했다.
- 요청한 첫 차단 중단 정책 적용. main push·workflow 수동 실행·CI·configure-pages·deploy는 미실행. 재시도0. 공개 URL 접근도 미실행이며 기존 게시 여부 미확인.
- `codex/information-processing-cbt` 브랜치는 코드 보존 용도다. push 자동 실행은 main에만 정의되어 있으므로 이 브랜치 push는 배포하지 않는다. 다른 프로젝트에는 쓰기 작업하지 않았다.
- 필요한 사용자 첫 동작: 환경 네트워크 허용 목록에 `api.github.com`을 추가하고 저장. 이후 사용자가 직접 마무리한다. Pages 설정 미확인 상태이므로 지금 Source 변경이 필요하다고 단정하지 않는다.


이번 1,000문항 확장에서도 기존 배포 중단 상태를 유지한다. main push나 workflow 실행, Pages 접근·재시도는 하지 않고 코드 보존 브랜치에만 반영한다.
